{{ sec(1, "Propósito de la etapa y datos utilizados") }}

R4 describió el EVA con conteos de registros por una dimensión a la vez. R5 construye un modelo multidimensional para medir volúmenes (toneladas, hectáreas, rendimiento, tasa de cosecha) desde varias perspectivas simultáneas y en distintos niveles de detalle, con el fin de descubrir conocimientos que el análisis exploratorio no podía mostrar.

Fuente

EVA — Evaluaciones Agropecuarias Municipales (MinAgricultura/UPRA, datos.gov.co), tratado en R2 y R3: app/static/data/R2/eva_basicos.json.

Cobertura

{{ anio_min }}–{{ anio_max }} · {{ resumen.municipios | miles }} municipios de {{ total_depts }} departamentos · 6 cultivos básicos · {{ resumen.registros | miles }} registros, todos cargados.

Limitaciones de calidad

{{ incoherentes | miles }} filas ({{ incoherentes_pct }} %) con área cosechada > sembrada; {{ cosecha_cero | miles }} con área cosechada 0; cambio de desagregación del maíz en 2021; plátano solo con periodo anual.

Cómo recorrer esta etapa

  1. Los cuatro análisis (sección 2): cada uno responde una pregunta, parte de un conocimiento evidente de R4 y tiene su propia página con explorador OLAP, matriz, gráficas y conocimientos.
  2. Operaciones OLAP (sección 3): ejemplos guiados de drill-down, roll-up, slice, dice y pivot que abren el análisis correspondiente ya configurado.
  3. Conocimientos descubiertos (sección 5): los ocho hallazgos con su cifra principal y el enlace al análisis que los sustenta.
  4. Construcción del modelo (secciones 7–12): modelo estrella, medidas, carga y validaciones en los que se apoyan todas las cifras.

{{ sec(6, "Limitaciones y conclusiones") }}

Limitaciones

  • EVA son evaluaciones municipales por consenso, no mediciones directas.
  • El {{ incoherentes_pct }} % de los hechos tiene área cosechada mayor que la sembrada; la tasa de cosecha es sensible a ese tratamiento.
  • Seis años no permiten separar tendencia de ciclos climáticos; las causas se plantean como hipótesis.
  • Las toneladas no miden aporte nutricional ni acceso a los alimentos: son asociaciones de oferta, no causalidad sobre la seguridad alimentaria.

Conclusiones

  • Contar registros (R4) y medir volumen (R5) llevan a mapas distintos: la Orinoquía, la papa del altiplano y el maíz tradicional cambian de peso.
  • Los cambios importantes aparecen al bajar de nivel (municipio, semestre) o al cruzar el sistema productivo, no en los totales.
  • Para la seguridad alimentaria, los puntos frágiles son el maíz tradicional del Caribe y los choques puntuales de cosecha de arroz.
Construcción del modelo
{{ sec(7, "Unidad de análisis y granularidad") }}

Unidad de análisis

La producción de un cultivo básico en un municipio: es el objeto sobre el que se formulan las preguntas (dónde, cuándo, cuánto y con qué sistema se produce).

Granularidad de la tabla de hechos

Cada fila de fact_produccion_agricola es 1 municipio × 1 desagregación de cultivo × 1 periodo agrícola (semestre A/B para transitorios, año para el plátano). Es más fina que la unidad de análisis: un cultivo en un municipio y un año puede tener varias filas (dos semestres, varias desagregaciones), y las medidas se agregan hasta el nivel que pide cada pregunta.

{{ sec(8, "Modelo estrella") }}
{% set pos = {"dim_territorio": (20, 20), "dim_tiempo": (640, 20), "dim_cultivo": (20, 262), "dim_sistema_productivo": (640, 262)} %}

La tabla de hechos fact_produccion_agricola registra la producción agrícola municipal de los cultivos básicos. Se relaciona con cada dimensión por una clave sustituta (1 dimensión : N hechos); la restricción UNIQUE (territorio_key, cultivo_key, tiempo_key) garantiza la granularidad y, como cada hecho tiene una sola fila en cada dimensión, los JOIN no multiplican valores. La clave 0 de cada dimensión es el miembro Desconocido para claves faltantes (hoy ningún hecho lo usa).

Las cuatro dimensiones son perspectivas reales del problema: dónde se produce (territorio), cuándo (tiempo), qué (cultivo) y cómo / para qué (sistema productivo). El sistema productivo viene de EVA, que lo codifica dentro del nombre de la desagregación; separarlo en una dimensión permite comparar tecnificado vs. tradicional de forma consistente antes y después del cambio de desagregación del maíz en 2021.

Herramientas

  • SQLite: base relacional en un archivo, incluida en Python y consultable desde Flask sin servidor; funciona en Render (el SQL Server de R3 no está disponible allí).

  • Flask + Chart.js: API OLAP con niveles y medidas en lista blanca, y vistas interactivas.

Faltantes, categorías desconocidas y respuestas negativas

Valor faltante → NULL

No hay dato. Se carga como NULL, nunca como 0, para que SUM lo ignore y no se confunda con una cosecha nula. En el EVA tratado no hay faltantes en las medidas (validación de arriba).

Categoría desconocida → clave 0

Hay hecho pero no se identifica su municipio, cultivo o sistema. Va al miembro «Desconocido» de cada dimensión y se excluye de los filtros. Hoy ningún hecho lo usa.

Respuesta negativa → 0

EVA reporta que no hubo cosecha: {{ cosecha_cero | miles }} hechos con área cosechada y producción 0. Es un valor real: baja la tasa de cosecha y suma área no cosechada, pero no entra en el rendimiento (su denominador es el área cosechada).
