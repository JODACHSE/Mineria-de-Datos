{{ report_h2("8", "Re-ejecución del mismo lote sin duplicados") }}

Al ejecutar un paquete con una clave de lote que ya existe, etl.usp_AbrirLote borra en cascada lo que ese lote cargó (staging, limpios, revisión, límites IQR y unidades), registra LOTE_REABIERTO y vuelve a cargar con el mismo IdLote. Resultado esperado para el mismo lote en dos ejecuciones:

{{ report_h2("9", "Cómo reproducirlo") }}
  1. Ejecutar en SQL Server, en orden, etapa3/sql/01_esquemas_y_tablas.sql, 02_procedimientos.sql y 03_catalogos.sql.
  2. Abrir etapa3/ssis/R3.slnx en Visual Studio con la extensión SQL Server Integration Services Projects.
  3. Ajustar los parámetros pRutaCsv* de Project.params a la carpeta app/data del equipo (la conexión usa autenticación de Windows: no hay contraseñas).
  4. Ejecutar EVA.dtsx y FAOSTAT.dtsx con pLoteClave = EVA-I1 / FAOSTAT-I1 y así para cada iteración.
  5. Revisar las evidencias con etapa3/sql/04_consultas_verificacion.sql y comparar con python scripts/etapa3_iteraciones.py.
