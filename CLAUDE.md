This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Development server
python run.py                        # http://127.0.0.1:5000

# Setup from scratch (installs dev deps + creates .env)
./setup.sh                           # Linux/macOS
setup.bat                            # Windows

# Manual setup
pip install -r requirements-dev.txt
cp .env.example .env

# Run all tests
pytest

# Run a single test file
pytest tests/test_quality.py

# Regenerate datasets (scripts run offline, not Flask context)
python scripts/fetch_faostat.py      # requires FAOSTAT_TOKEN in .env
python scripts/rebuild_chart.py
python scripts/process_eva.py
python scripts/clean_datasets.py
python scripts/etapa3_iteraciones.py # → app/static/data/R3/iteraciones.json
python scripts/R5/build_star.py       # → app/data/R5/wololo_dw.sqlite (modelo estrella + validaciones)
python scripts/R5/export_docs.py      # → docs/R5/analisis_multidimensional.md

# Production (Render)
gunicorn run:app --workers 1 --threads 4 --timeout 120 --preload
```

## Architecture

**Flask app factory** at `app/__init__.py` → `create_app()`. Two blueprints:
- `pages_bp` (`app/routes/pages.py`): HTML views (`/`, `/r1`, `/r2`, `/r3`, `/r4`, `/r4/territorial`, `/r4/temporal`, `/r4/relacional`, `/r5`, `/r5/<slug>`, `/entregables`, `/sobre-nosotros`)
- `api_bp` (`app/routes/api.py`): JSON API (`/api/dataset/<name>`, `/api/quality/<name>`, `/api/profile/<name>`, `/api/r5/<slug>`)

**Service layer** (`app/services/`):
- `datasets.py`: loads and in-memory caches the static JSON files from `app/static/data/R1/` and `R2/`. All cache is process-lifetime (immutable JSON, regenerated by offline scripts). Page contexts (R1/R2/R3) are also cached under `"ctx:r1"` etc.
- `reports.py`: builds template contexts for R1 and R2 and handles API query/pagination logic.
- `etapa3.py`: builds the R3 context (SSIS ETL results, iteraciones.json, video URL).
- `etapa4.py`: builds the R4 contexts (4 dimension pages: poblacional, territorial, temporal, relacional) from the R2-treated EVA dataset.

**Quality module** (`app/quality.py`): pure Python, no Flask dependency — used by both routes and offline scripts.
- `DATASETS` dict maps logical names (`qcl`, `qcl_basicos`, `fs`, `eva_basicos`) to JSON filenames.
- `DATASET_SCHEMA` defines per-dataset column metadata, key fields, filter fields, and quality-check rules.
- `compute_quality()` is frozen (R1 contract — do not change its output keys).
- `compute_dimensions()` implements the 6 R2 quality dimensions.
- `build_problem_inventory()` generates the R2 problem inventory automatically from profiling.

**Data flow**:
1. Raw CSVs live in `app/data/` (traceability only).
2. Offline scripts (`scripts/`) produce curated JSON into `app/static/data/R1/` (raw) and `R2/` (treated + `log_tratamiento.json`).
3. Flask serves the JSON directly via `datasets.py`; quality is recomputed on every request (fast: Python-only, no pandas).

**R3 (SSIS ETL)**:
- SSIS solution (Visual Studio project) in `scripts/R3/` (`EVA.dtsx`, `FAOSTAT.dtsx`, `R3.dtproj`).
- SQL schema/stored procedures: master copy in `SQL/` (repo root); downloadable copies served from `app/static/etapas/r3/sql/`.
- `app/static/etapas/r3/R3.zip` must contain only the solution (`R3.slnx`, `*.dtsx`, `Project.params`, `R3.database`, `R3.dtproj`) — never `.vs/`, `bin/`, `obj/` or `*.user`.
- Detailed technical write-ups of each package in `docs/R3/` (not wired into the Flask app — reference docs only).
- `VIDEO_ETAPA3_URL` env var controls the YouTube embed on `/r3`.

**R4 (Conocimiento evidente)**:
- 4 analysis questions (poblacional, territorial, temporal, relacional-multivariada), each with indicators, visualizations, filters and documented "conocimientos evidentes". Content lives in `app/templates/etapas/r4/*.html` (shared macros in `etapas/r4/_macros.html`), built from `etapa4.py`.
- Power BI report (`.pbix`) replicating the same 4 questions: `docs/R4/EVA_PowerBI_wololo.pbix`, downloadable at `/docs/R4/EVA_PowerBI_wololo.pbix` (the `/docs/` route serves only `POWERBI_PBIX_FILE`). Embedded pages come from the `POWERBI_R4_*_URL` settings.
- `POWERBI_REPORT_URL` env var controls the "Abrir informe" button on `/r4`; it renders a "Próximamente" badge while unset.

**R5 (Análisis multidimensional)**:
- Star schema in SQLite (`app/data/R5/wololo_dw.sqlite`, generated, not versioned) built from the R2-treated EVA JSON by `app/services/dw.py` (`ensure()` rebuilds at startup if missing/stale). DDL and SQL reference queries in `SQL/R5/`.
- `app/services/olap.py`: whitelisted levels/measures → GROUP BY queries; totals and non-additive measures (rendimiento, tasa de cosecha, COUNT DISTINCT) are recomputed per query, never summed. Also `validations()` (model vs. source JSON).
- `app/services/etapa5.py`: the 4 views (`VISTAS`), guided OLAP examples (`EJEMPLOS`), R4 → R5 traceability (`R4_RELACION`) and the 8 conocimientos, whose figures are computed from the model. `scripts/R5/export_docs.py` exports all of it to `docs/R5/`.
- Missing measures load as NULL (never 0); 0 means a reported negative (e.g. no harvest); dimension key 0 = "Desconocido".

**Organization by view**: anything used by a single stage lives under an `rN/` folder — `templates/etapas/rN/`, `static/js/etapas/rN/`, `static/etapas/rN/` (downloads, images), `static/data/RN/`, `docs/RN/`, `scripts/RN/`. Site-level pages (home, entregables, about) are in `templates/pages/`; page-only CSS in `static/css/pages/<view>.css` loaded via `{% block head %}`.

**Frontend**: Bootstrap 5.3.8 (no build step).
- CSS in layers, loaded in order by `layouts/base.html`: `static/css/tokens.css` (overrides `--bs-*` vars, brand + per-stage `--tone-N-rgb`, light/dark) → `base.css` → `layout.css` (header, mobile menu, report sidebar, footer) → `components.css`.
- JS (ES modules) in `static/js/`: `core/` (layout, theme, sound, motion, notify), `features/` (shared by several views: charts, explorer, roadmap), `etapas/rN/` (single-stage code: R4 filters, R5 olap, R6 charts). `static/vendor/` holds hash-verified third-party modules (uisfx).
- `core/layout.js` writes the real header height to `--header-h` (and the mobile "En esta página" bar to `--subnav-h`); `html { scroll-padding-top }` uses them so anchors never land under the header. It also runs the report scrollspy (Bootstrap's is not used).
- Stages in the navbar/footer come from `app/etapas.py` (`icono`, `tono` fields).
- Chart.js reads Bootstrap CSS variables for colors and redraws on theme change.

**Security** (`app/security.py`): per-request CSP nonce (`csp_nonce()` in templates) — never add inline `<script>` without `nonce="{{ csp_nonce() }}"` nor inline event handlers; new iframe hosts must be added to `FRAME_SOURCES`. `/docs/<file>` only serves `POWERBI_PBIX_FILE`.

**Config** (`app/config.py`): all sensitive values from env vars; metadata (project title, team, university) injected into every template via `context_processor`. `BASE_DIR` is the repo root.

## Key constraints

- `compute_quality()` output keys are a **frozen contract** (R1 is already graded). Do not rename or remove keys from its return dict.
- `app/static/data/` JSON files are generated offline; never write them from within the Flask app.
- Production uses `--preload` so the 48 932-row EVA dataset is parsed once at startup and cached for the lifetime of the process.
- `requirements.txt` is for production (Render) — only Flask, python-dotenv, gunicorn. `pandas`, `requests`, `faostat`, `pytest` belong in `requirements-dev.txt`.

## Comment style

Spanish, brief, one format everywhere. Comment only *why* or a non-obvious rule — never restate the code.
- File header (one line, two or three only if essential): `"""Qué hace."""` (Python; scripts add `Uso:` and `Entrada/Salida:`), `/** archivo — qué hace. */` (JS), `/* archivo — qué hace */` (CSS), `{# Qué es. #}` (templates).
- Section markers: `# --- Nombre ---`, `// --- Nombre ---`, `/* --- Nombre --- */`, `{# --- Nombre --- #}`.
- Keep tool directives (`# noqa`, `# type: ignore`, `NOSONAR`, `shellcheck`).
